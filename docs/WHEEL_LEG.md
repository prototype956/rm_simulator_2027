# 轮腿模型、机构与火控挂点

`wheel_leg` 使用用户提供的 URDF，双方步兵、哨兵均可选择；图形与无渲染入口共享资产及机构控制。角色资源见 [联盟赛规则](RMUL_2027.md)，通用操作见 [多车型环境](MULTIROBOT_FIRE_CONTROL.md)。

## 启动与动作

在 NUC 桌面终端进入 `/home/nuc/Workspace/bevy_robomaster_simulator` 后运行：

```bash
bash scripts/run_multirobot.sh infantry wheel_leg standard
bash scripts/run_multirobot.sh sentry wheel_leg wheel_leg
```

- X 举升／收腿；完全举升后向合法 200mm 高地边沿持续驾驶，自动完成辅助支撑接台、车体推进、两侧驱动轮转移及落稳。车头与边沿法向夹角不超过 15°，横移／倒车不触发辅助。
- 接近阶段松键取消；进入支撑转移后松键，先到可靠支撑状态再交回驾驶。完成后保留举升，可再次 X 在台面收腿；下台使用正常驾驶及重力接地。
- F6 独立跳跃，顺序为准备、蹬伸、腾空收腿和落台缓冲。起点距边沿至少 0.38m，检索上限 0.95m；重复请求不叠加，空中松键不冻结。
- Alt+X／Alt+F6 作用于当前敌方假人。C 保留假人云台控制，J 保留假人移动。F3 切换视角后 WASD 驾驶；自由相机模式的 WASD 控制相机。
- HUD 显示动作阶段与受阻原因；墙、挡边、隧道顶板及被占落点不作为可上台目标。

## 动作时序和约束

| 项目 | 当前参数（仿真时间） |
|---|---|
| 200mm 举升 | 0.20s，举升速度 1.0m/s |
| 举升完成后距边沿 0.7m 驶入 | 约 1.20s；接近 1.2m/s，支撑转移 0.88s |
| 跳跃准备／蹬伸／缓冲 | 0.12／0.18／0.10s |
| 200mm 台阶跳跃总时长 | 约 0.81s；9.81m/s² 下腾空约 0.412s |
| 动作预检采样 | 间隔不超过 5ms |
| 仿真关节速度上限 | 25rad/s，检查保留 1% 数值容差 |

时序参考 [举升驶入视频](https://www.bilibili.com/video/BV1aqcUzLESC/) 和 [连续跳台视频](https://www.bilibili.com/video/BV1bYNcz7EpQ/)，按约 0.1s 连续帧估计节奏，不是电机标定。原 URDF 八个关节的 5rad/s 导出值保持原样；运行时速度上限是独立的火控仿真近似。没有加快整个仿真时钟，图形和训练的实际物理步长仍由各自入口设置。

举升驶入按两侧轮心和辅助支撑逐步转移接触，不预先把整车抬到台面再平移。跳跃根位置按仿真重力推进，姿态和收腿受约束。预检与执行均检查角限位、连杆长度、碰撞、扫掠空间和落点支撑；支撑丢失转为重力下落并恢复姿态。

普通驾驶、场景脚本及跨越控制器互斥地拥有根刚体。相机、枪口、装甲和碰撞共用实际姿态；装甲速度含机构升降、俯仰及根运动，根速度不重复累加。轮腿动作不统一禁射，仍检查资源、枪口和遮挡。战亡停止主动动作，R 清除动作、恢复状态、增益、命中历史及在途弹丸。

训练的 `motion.kind="climb"` 与 `"jump"` 使用同一控制器，各完成一次上台后保持位置；没有自动重复跳跃或课程调度。场景字段见 [训练场景](TRAINING_SCENARIOS.md)。

## 原始资产与坐标

原包保存在 `assets/robots/wheel_leg/source.zip`，来源 `UZ-05-open总装.STEP`，9 连杆、8 个 revolute 关节。SHA-256：

```text
ef3ab28628b7315b7e3cfe5a38714b17bb24942506be2c8ec3666165de702be1
```

遵循 URDF 的 visual origin、RPY 与 mesh scale，毫米只转换一次到米。CAD 轮轴 X、枪管 +Y、向上 +Z，适配到 Bevy X、-Z、+Y；将任意基准 X=54.449997mm 移到车体中线。默认根高度约 275.495mm，轮面保留约 5mm 物理余量。不能用导出报告的 `z_up_x_forward` 声明替代实体方向检查。

导出报告中未分配的 `part_1162`、`part_1172`、`part_602` 未进入 URDF，导入器没有补造。两条轮腿使用原连杆长度与有界逆运动学，轮轴补偿姿态；不是四根伸缩杆模型。

## 装甲、外观与碰撞

派生 URDF、GLB 及碰撞同时移除 64 个原 CAD 装甲零件：`part_074–089`、`094–109`、`513–528`、`533–548`。保留外部支架 `072/073/092/093/511/512/531/532`，以原面板 `079/099/518/538` 的正面安装平面替换为现有黑色装甲。保留四块装甲原尺寸、灯条、编号、命中语义、前后高度差与倾角；安装中心误差约束 1mm，法向误差约束 0.5°。清单与矩阵见 `replacement.json`。

结构采用 sRGB(14,14,14) 黑色；GLB 线性 PBR 基色约 0.004391442，金属度 175/255、粗糙度 238/255。装甲数字和灯条保留原功能。根实体没有固定地面支撑圆柱；底盘为 296 个过滤后的 CAD 零件凸包，其余八个连杆各自凸包并随关节运动。凸包封闭小孔，细小紧固件不逐件碰撞。

## 校准与重新生成

相机和枪口以云台 pitch 零位枢轴为基准，单位米；临时标定值保存在 `assets/robots/wheel_leg/calibration.json`。yaw 支架只跟随 yaw，pitch 总成和火控挂点跟随既有云台控制器；未将导出的默认云台限位或 effort 当成实车标定。装甲随底盘运动，云台独立。

修改相机／枪口校准后重新导入，再重启仿真。导入会读取已有校准，装甲矩阵则依据 CAD 面板重新计算。生成资产使用 Python＋numpy，无需 Blender、ROS 或运行时 URDF 依赖：

```bash
python3 -B scripts/assets/import_wheel_leg.py assets/robots/wheel_leg/source.zip
python3 -B -m unittest discover -s tests -p 'test_*.py'
```

`robot.urdf`、`wheel_leg.glb`、`rig.json`、`calibration.json`、`replacement.json` 必须成套更新；不要手工修改生成的 `rig.json`。来源哈希或面板几何不匹配时导入拒绝套用零件过滤清单。检查入口统一见 [测试与工具](TESTING.md)。

## 近似与人工核对

用于火控训练的连续姿态与理想支撑约束，不模拟关节力矩、平衡、轮胎动力学或能量。质量、驱动和云台响应沿用仿真参数；台阶首版限 200mm。CAD 面板对齐精度不代表实车标定精度，相机、枪口与真实形变仍需实测。

驾驶、视角、机构按键及视觉跟踪手感由操作者手动验收。自动检查不操作 NoMachine、不注入桌面键鼠；旧版短时命中数据不视为当前快动作下的火控通过结论。
