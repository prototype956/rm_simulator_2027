# 战斗机制与 Talos 协议

本文说明共享实现，保留原文件名以兼容已有引用。当前联盟赛参数及规则解释见 [RMUL 2027](RMUL_2027.md)，使用方式见 [多车型环境](MULTIROBOT_FIRE_CONTROL.md)。`legacy` 与 `rmul2027` 是不同规则集，不能将早期训练简化当作联盟赛规则。

## 配置和状态归属

```toml
[combat]
ruleset = "rmul2027"
controlled = "infantry_health_cooling"
target = "sentry"
controlled_allowance = { mode = "limited", initial = 200 }
target_allowance = { mode = "limited", initial = 750 }
```

- 每个机器人根实体独占 `RobotIdentity`、`RobotCombatState`，包括队伍、角色、规则快照、生命、热量、弹量及发射机构。装甲、底盘和云台通过 `RobotMember` 关联根实体，不各自复制血量。
- 稳定 ID 表示场景槽位：受控车 1、目标车 2、旧英雄假人 3；不是比赛裁判编号或视觉分类标签。重装近似靶与旧英雄假人的配置含义不同。
- 省略额度配置时为 `unlimited`；有限额度用 `limited` 与 `initial` 指定。无限额度仍受热量、生命和机械间隔限制。联盟赛多车型训练会强制使用真实资源，见 [训练场景](TRAINING_SCENARIOS.md)。
- 角色、额度和发射机构参数在生成或 R 重置时复制。有效热更新暂存至下次重置；非法配置拒绝应用。地图切换及程序升级需要重启。

## 请求与实际出膛

`combat::shooting::request_fire` 是键盘、手柄及外部控制的统一 17mm 请求入口。手动长按按机械间隔重复请求；Talos 的 `fire_advice` 采用上升沿语义。

| 参数 | 含义 |
|---|---|
| `projectile.speed` | 相对枪口初速，有限且大于 0、不超过 25m/s；世界速度叠加底盘平移 |
| `projectile.cooldown` | 模拟机械最小出膛间隔，默认 0.05s；不是裁判规则 |
| `projectile.launch_delay_s` | 额外供弹延迟，默认 0；与云台命令延迟独立 |

发射按固定物理时钟结算，截止时刻向后对齐物理步。先处理到期供弹，再按 FIFO 处理新请求；队列上限 256，每车同一时刻最多出膛一发。不按历史命令时间补造弹丸，拒绝请求也不会积压至解锁后补射。

非零供弹延迟下，每车最多等待一发。到期重新检查生命、热锁、额度、机构和枪口，并读取实际完整挂点位姿。只有创建弹丸后，才扣弹、增热、增加实际出膛数和触发震动；等待或拒绝都不计数。关闭外部控制取消未出膛的外部请求，不影响在途弹丸。

每颗弹丸携带唯一 `ProjectileShot` ID、发射者、请求来源、仿真出膛时间、枪口位姿和初速度。没有模拟弹仓、兑换和额外的云台转动切向出膛速度。飞镖不通过这条 17mm 入口。

## 热量和额度

各车独立保存热量，内部用十分之一单位整数结算。每发出膛增加 10；每 100ms 冷却预设速率的十分之一，最低为零。跨越多个截止时刻时逐拍补结算，零热量期间不积累未来冷却额度。

| 条件 | 行为 |
|---|---|
| 热量等于普通上限 | 不新增锁定；已有锁定继续保持 |
| 热量超过普通上限 | 普通锁定，直至冷却到零才解除 |
| 热量达到上限＋100 | 整局锁定，冷却到零也不解除 |
| R 重置 | 清除热量和锁定，恢复当前配置初始额度 |

每个物理步先冷却，再检查请求、创建弹丸和增热。尚未锁定时允许跨过普通上限的那一发；不提前预留 10 热量。普通锁定期间取消待供弹请求，零额度同样禁射。整局锁定采用流程图的 `≥` 口径，与手册正文严格 `>` 的差异保留于 [联盟赛说明](RMUL_2027.md)。

## 命中、战亡和重置

弹丸按首次有效物理接触消耗，同一弹丸只结算一次。车体或环境命中不造成装甲伤害；自身、同队和已战亡目标不重复扣血。实际伤害不超过目标剩余 HP。

`legacy` 保留早期每次装甲命中原始 20HP 的简化；`rmul2027` 额外执行正面相对法向速度、每块装甲检测间隔和增益，详见 [规则](RMUL_2027.md)。碰撞速度取物理求解前的缓存，包含底盘和机构运动。

战亡停止主动底盘、云台和机构驱动及发射，取消供弹，保留碰撞、被动惯性和在途弹丸；没有自动复活。R 统一恢复生命、额度、热量、动作和增益，清除命中历史、请求及在途弹丸，并关闭自瞄。图形 R 重置推进回合编号，进程时钟、采样序号和事件 ID 继续递增；训练 Reset 另由训练后端重建场景。

## HUD、遥测和策略边界

`preview.enabled` 控制窗口预览，`heat_hud`、`health_hud` 控制战斗显示。HUD 读取当前物理状态，仅出现在操作者窗口，不进入 Talos 相机图像。

Talos v7 图像快照携带稳定机器人 ID、队伍、角色、生命、热量、额度与物理禁射原因；装甲真值用 `owner_robot_id` 关联归属。战斗结算后在 `FixedLast` 构造评估真值，自身裁判状态按 100ms 采样；携带实际样本时间与序号，重复样本不伪装成更新。

- `/referee/self`：自身最近裁判样本。
- `/simulation/combat/evaluation`：机器人真值、伤害归因、统计与事件，仅供评估。
- 敌方 HP、车型真值及未来轨迹不进入正式火控或策略观测。窗口 HUD 不额外模拟裁判采样延迟。

事件缓存最多 1024 条、每帧传最近 64 条，描述最多 231 字节 UTF-8。客户端按 ID 去重并检测跳号；`events_dropped` 只统计内部淘汰，不保证传输无遗漏。累计统计读取状态计数，不从重复事件累加。

v7 命令携带来源图像的回合、序号与 epoch 采集时间。有效目标命令必须属于当前回合、来源时间非零并通过 F5 时间门限；旧图像产生的新命令仍会被拒绝。停止命令保留停止能力；重置不会撤回已送入视觉线程的旧图像或重置跟踪器内部估计。
